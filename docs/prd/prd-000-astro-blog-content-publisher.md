# astro-blog-content-publisher: требования к первой версии

Статус: требования первой версии 0.1.0. Основа — согласованный с пользователем процесс из семи этапов и решение использовать Astro для лендинга и блога.

## Задача

Пользователь поручает агенту подготовку статьи для SaaS-блога. Агент должен изучить опубликованный контент, выбрать тему, исследовать её, написать и отредактировать статью, проверить SEO/GEO и встроить результат в существующий Astro-проект. Результат должен содержать доказательства выполненных проверок и точный статус публикации.

## Пользователь и сценарии

Основной пользователь — владелец SaaS или редактор, работающий через Codex либо Claude. Первый проект применения — блог Traq Money; сам skill не привязан к его домену, языку, тарифам или хостингу.

Поддерживаются выбор темы с брифом, подготовка текста без публикации, проверенный предпросмотр, полный цикл с разрешённой публикацией и обновление существующей статьи. Агент сохраняет границы конкретного поручения.

## Состав результата

- Корневой skill `astro-blog-content-publisher` с инструкциями и полезными ссылочными материалами.
- Устанавливаемый через `npx` npm-пакет с CLI `install`, `check` и `list`.
- 12 сторонних skills, поставляемых вместе с пакетом: `product-marketing-context`, `content-strategy`, `seo-content-brief`, `content-research-writer`, `seo-content`, `seo-audit`, `ai-seo`, `english-humanizer`, `humanizer-ru`, `copy-editing`, `astro-framework`, `webapp-testing`.
- Манифест происхождения и ревизий, контрольные суммы, лицензии и сведения о внесённых изменениях.
- Русская инструкция установки, примеры вызова и проверки пакета.

## Редакционный процесс

| Этап | Обязательный результат |
|---|---|
| Подготовка | Проверенный контекст продукта и проекта без дублирования существующих документов |
| 1. Анализ | Рекомендуемая тема, проверка пересечений, поисковое намерение, бриф |
| 2. Исследование | Черновик, подтверждающие источники, явные допущения |
| 3. SEO | Полнота ответа, структура, метаданные, настоящие внутренние ссылки |
| 4. GEO/AI | Ясные объяснения и сущности, пригодные для корректного цитирования |
| 5. Редактура | Естественный язык с сохранением фактов и смысла |
| 6. Проверка | Исправленные конкретные замечания после редактуры |
| 7. Astro | Интеграция, сборка, проверка HTML и браузера; deploy и публичная проверка при разрешении |

Каждый из семи этапов требует чтения и применения стороннего skill. Зависимости устанавливаются рядом с корневым skill. Отсутствие обязательной зависимости отражается как конкретная проблема установки; агент не отмечает этап выполненным без неё.

## Установка

Требуется Node.js 20+. По умолчанию Codex получает skills в `.agents/skills` текущего проекта. Поддерживаются Claude, оба агента, глобальная установка и явный `--target`. Явный каталог не совмещается с выбором агента или глобальным режимом.

До записи проверяются весь набор и все целевые каталоги. Совпадающие версии сохраняются; отличающиеся варианты вызывают конфликт без перезаписи. Установка не скачивает зависимости из отдельных репозиториев и не выполняет lifecycle hooks. `--dry-run` не меняет целевые файлы. `check` проверяет установленный набор.

Пакет проверяется и передаётся как локальный `.tgz`. Публикация в npm registry требует отдельного поручения.

## Границы

Версия 0.1.0 не создаёт новый Astro-сайт, не мигрирует блог, не добавляет Hugo или CMS, не переделывает дизайн и не навязывает провайдера deploy. Она не выполняет поиск секретов вне задачи и не сохраняет их в контенте.

Пакет не заменяет браузер, credentials, инфраструктуру хостинга или доступ к аналитике. Если нужного инструмента нет, агент сообщает, какая проверка не выполнена.

Финансовые и другие изменяемые факты проверяются по актуальным первичным источникам. Нельзя выдумывать метрики, опыт, авторов, отзывы или цитаты. Списки ключей, размер текста и условные баллы не заменяют содержательную проверку. Гарантии ранжирования, AI-цитирований и обход AI-детекторов исключены.

## Критерии приёмки

1. Архив запускается через `npx --package <локальный архив>` и устанавливает корневой skill вместе со всеми обязательными зависимостями в изолированный каталог.
2. Проверка установленного набора выявляет отсутствующие или изменённые файлы. Повторная установка совпадающего набора не портит его; конфликтующий файл сохраняется.
3. Инструкции каждого этапа называют сторонние skills, путь их загрузки, результат и ограничения проверки.
4. Корневой skill допускает частичные поручения и не публикует статью по запросу только на черновик. Явное разрешение опубликовать не вызывает повторных ритуальных подтверждений.
5. Для интеграции используются схема, шаблон и версия фактического Astro-проекта. Готовность опирается на сборку и проверку страницы; факт индексации не выводится из успешного deploy.
6. В пакет не входят личные пути, рабочие журналы, credentials или секреты. Зависимости имеют проверяемое происхождение и разрешение на распространение.

## Оставшиеся решения

Для локальной версии дополнительных решений о контентном процессе не требуется. Перед публичным релизом нужно отдельно выбрать канал распространения и выполнить разрешённую публикацию пакета. Настройки конкретного Astro-блога, авторы и способ deploy определяются в его репозитории при применении skill.
