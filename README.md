# astro-blog-content-publisher

Skill для подготовки и публикации статей в существующем блоге на Astro: выбрать тему, собрать источники, написать текст, проверить SEO/GEO, отредактировать язык и проверить готовую страницу.

Установщик добавляет корневой skill и 12 сторонних skills в одну папку. Зависимости входят в пакет с закреплёнными версиями, происхождением, лицензиями и контрольными суммами. Во время установки их не нужно скачивать из отдельных репозиториев.

## Глобальная установка для Codex из GitHub

Нужен Node.js 20 или новее, npm с `npx` и Git с доступом к [репозиторию](https://github.com/svishniakov/astro-blog-content-publisher). Для закрытого репозитория у вашей Git-аутентификации должны быть права на чтение. Не вставляйте токены в команды, URL или файлы проекта.

Установка корневого skill и всех зависимостей в `~/.codex/skills`:

```sh
npx --yes --package=github:svishniakov/astro-blog-content-publisher astro-blog-content-publisher install --global
npx --yes --package=github:svishniakov/astro-blog-content-publisher astro-blog-content-publisher check --global
```

Первая команда устанавливает набор; вторая проверяет его файлы. Для просмотра плана без записи добавьте `--dry-run` к команде `install`.

Пакет пока не опубликован в npm registry: короткая команда `npx astro-blog-content-publisher` потребует отдельной публикации. Приведённые команды указывают GitHub как источник пакета.

## Другие варианты установки

Без `--global` Codex получает skills в `.agents/skills` текущего проекта. Для Claude используйте `--agent claude`: каталог проекта — `.claude/skills`, глобальный каталог — `~/.claude/skills`. Для обоих агентов используйте `--agent all`. Передавайте одинаковые параметры командам `install` и `check`.

Вместо профиля агента можно явно указать каталог skills:

```sh
npx --yes --package=github:svishniakov/astro-blog-content-publisher astro-blog-content-publisher install --target /path/to/skills
npx --yes --package=github:svishniakov/astro-blog-content-publisher astro-blog-content-publisher check --target /path/to/skills
```

`--target` не сочетается с `--agent` и `--global`. Команда `list` показывает состав пакета. `--dry-run` показывает план без изменения файлов.

Если установленный skill отличается от версии в пакете, установщик сообщает конфликт и прекращает установку целиком до записи файлов. Он сохраняет существующие варианты. Используйте отдельный каталог проекта или `--target`, либо явно разберите конфликт перед повторной установкой. Автоматического обновления и принудительной перезаписи нет.

### Альтернатива: локальный архив

В папке исходников соберите архив:

```sh
npm test
npm run validate
npm run smoke
npm pack --dry-run
npm pack
```

Сохраните абсолютный путь к архиву, затем перейдите в нужный Astro-проект:

```sh
publisher_package="$PWD/astro-blog-content-publisher-0.1.0.tgz"
cd /path/to/your-astro-project
npx --yes --package "$publisher_package" astro-blog-content-publisher install --dry-run
npx --yes --package "$publisher_package" astro-blog-content-publisher install
npx --yes --package "$publisher_package" astro-blog-content-publisher check
```

Для глобальной установки из архива добавьте `--global` к `install` и `check`.

## Что устанавливается

| Этап | Сторонние skills | Результат |
|---|---|---|
| Подготовка контекста | `product-marketing-context` | Аудитория, позиционирование, возможности продукта и стиль |
| 1. Анализ блога и выбор темы | `content-strategy`, `seo-content-brief` | Обоснованная тема и бриф с учётом существующих статей |
| 2. Исследование и черновик | `content-research-writer` | Статья с проверяемыми источниками и примерами |
| 3. SEO | `seo-content`, `seo-audit` | Исправленный текст, метаданные, внутренние ссылки |
| 4. GEO/AI | `ai-seo` | Ясные определения, точные сущности, подтверждённые ответы |
| 5. Редактура | `english-humanizer` или `humanizer-ru`, затем `copy-editing` | Естественный текст с сохранением фактов и ссылок |
| 6. Повторная проверка | `seo-content`, `seo-audit`, `ai-seo` | Проверка, что редактура сохранила смысл и поисковую ценность |
| 7. Публикация в Astro | `astro-framework`, `webapp-testing`, `seo-audit` | Интеграция, сборка, проверка страницы и разрешённая публикация |

Корневой skill читает и применяет зависимости на соответствующем этапе. Сам установщик не пишет статьи и не запускает deploy. Источники, закреплённые ревизии и изменения копий сторонних skills указаны в [манифесте зависимостей](skills-lock.json); тексты лицензий поставляются с ними.

## Как пользоваться

После глобальной установки `$astro-blog-content-publisher` доступен из любого проекта Codex. Откройте нужный Astro-проект и вызовите skill:

```text
Используй $astro-blog-content-publisher: изучи блог Traq Money,
предложи следующую тему и подготовь бриф. Статью пока не пиши.
```

```text
Используй $astro-blog-content-publisher: напиши англоязычную статью
по этому брифу, пройди SEO/GEO и редактуру, добавь её в Astro
и проверь локальный предпросмотр.
```

```text
Используй $astro-blog-content-publisher: обнови эту статью,
проверь источники и опубликуй через существующий deploy проекта.
```

Skill поддерживает отдельные этапы и обновление существующих статей. Явная команда опубликовать разрешает штатный deploy в пределах правил проекта. Запрос на черновик или предпросмотр заканчивается на этом результате. Коммиты требуют отдельного поручения.

## Что требуется от Astro-проекта

В проекте должны быть понятные правила хранения контента, схема метаданных, маршруты статей и общий шаблон. Skill использует фактическую версию Astro и существующие команды сборки и публикации. Если блог ещё не создан, агент подготовит контент и укажет, какое решение об инфраструктуре нужно принять перед интеграцией.

Markdown подходит для обычных статей; MDX используется при необходимости поддерживаемого компонента. Изображения проходят существующий pipeline Astro. Копирование файла в `public/` само по себе не оптимизирует его.

Пакет устанавливает инструкции и ресурсы skills. Он не устанавливает Astro, Python, браузеры, Playwright, MCP-серверы или инструменты хостинга; не выдаёт доступ к Search Console и не создаёт deploy credentials. Агент проверяет доступные инструменты и прямо сообщает, если не смог выполнить проверку.

По умолчанию публикация не привязана к Vercel или другой платформе. Используется настроенный способ проекта.

## Правила качества

Статья должна отвечать на задачу читателя и содержать проверяемые утверждения. Для финансовых примеров сохраняются расчёты, валюта, период и допущения; гипотетические данные обозначаются явно. Авторство, опыт и результаты клиентов не выдумываются.

Корневой skill уточняет спорные советы зависимостей: фиксированная плотность ключей, минимальный объём статьи, условный SEO-балл и обещание AI-цитирований не считаются критериями готовности. Редактура не используется для обхода AI-детекторов.

Успешная сборка, проверенный предпросмотр, публикация и индексация — отдельные состояния. Перед публикацией агент проверяет готовый HTML и страницу в браузере; после deploy — публичный URL. Поисковые позиции и попадание в AI-ответы не гарантируются.
